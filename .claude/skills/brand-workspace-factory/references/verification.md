# 交付前驗收 Verification

跑完九步之後逐條對。**唔好靠感覺，逐條 check。**

呢張清單存在嘅理由：一個生成得好齊全嘅工作台，同一個真正用得嘅工作台，分別通常唔喺於缺咗咩檔案，而喺於檔案入面係咪真嘢。下面每一條都係針對「睇落有，其實冇」嘅失敗模式。

---

## A. 地基（錯咗呢層，後面全部白做）

- [ ] `BIBLE.md` 一頁內
- [ ] 受眾寫到**認得出係邊個** —— 唔係「年輕媽媽」，而係有年齡、處境、心情、原話
- [ ] 語氣三行入面，「從來唔會」嗰行寫咗具體嘢（唔係「唔會唔專業」）
- [ ] 紅線每一條**可以機械式檢查**（可以寫成禁用詞掃描或存在性檢查）
- [ ] 紅線包含晒 archetype ＋ 所有 modifier 帶嚟嘅條目

## B. 語料（呢層決定「像唔像」）

- [ ] `02-voice-profile.md` 有信心度標記（高／中／低）
- [ ] 入面有**數字**：平均句長、emoji 密度、感嘆號次數、開場類型比例
- [ ] 有禁用詞清單（同行常用但呢個品牌從來冇用嘅）
- [ ] 有稱呼讀者嘅固定講法
- [ ] 如果用咗行業預設 → 檔案第一行有 ⚠️ 警告，交付訊息亦有講

**自測**：攞呢份檔案，唔睇任何原帖，寫一段 100 字。同真實帖擺埋一齊，分唔分得出？分得出即係唔夠具體。

## C. 資料庫

- [ ] 八個櫃桶檔案全部存在（就算空）
- [ ] 空嘅櫃桶有明寫「（空）」＋ 點解空 ＋ 點補
- [ ] `04-approved-claims.md` 如果空 → 有明寫「此檔案為空期間唔可以引用任何數字／個案」
- [ ] 所有爬回嚟嘅資料有 Source Receipt（標題／平台／作者／日期／連結）
- [ ] 原始資料同蒸餾產物分開存放

## D. 編制

- [ ] 人數符合公式（核心 5 ＋ 條件加開，上限 8）
- [ ] 每個角色按**產出物**分，唔係按平台或話題分
- [ ] 有 compliance modifier → QA 係獨立 agent，唔同文案共用
- [ ] 每份 `AGENTS.md` 六個欄位齊
- [ ] 每個角色嘅「交付成果」有**明確檔案路徑**，唔係「一份報告」
- [ ] 每個角色嘅 Rules 冇抽象廢話（隨機抽三條，每條問：可唔可以明顯違反？）

## E. 串連（最易斷嘅位）

- [ ] 每個 agent 嘅 Inputs 路徑，喺檔案系統入面真係存在
- [ ] 上游嘅交付檔名 = 下游嘅 Inputs 檔名（逐對核）
- [ ] 品牌資料只有一個真相來源（技能資料夾係引用，唔係複製）
- [ ] 流水線行得通：畫一次由選題到待審嘅路徑，每一步都有檔案接得上

**呢一項最多人失分。**生成嗰陣好容易寫咗「讀 insight-pack.md」但研究 agent 其實交緊 `insights.md`。逐對核。

## F. 工具與排程

- [ ] `config/tools.md` 每步寫咗：邊類工具、入咩、出咩、交俾邊個
- [ ] 工具寫**類型**唔係品牌名（工具會換）
- [ ] `config/schedule.md` 排程窗口符合平台同時區
- [ ] 第一個月設定係「只排到待審」，唔直接發布
- [ ] 唔會四個平台同日出同一內容

## G. 展示

- [ ] `dashboard/index.html` 打得開
- [ ] 睇得到：八站狀態、待審佇列、本週排程、最近決策
- [ ] 唔係淨係擺結果縮圖 —— 要見到**狀態同下一步邊個負責**

## H. 冒煙測試（唔跑呢個就當未完成）

由頭跑一條真實內容：選題 → 文案 → QA → 待審。

- [ ] 跑得完，冇 agent 搵唔到檔案
- [ ] 冇死循環（QA 同文案互相退回）
- [ ] 產出物落咗正確路徑
- [ ] **出嚟嗰篇嘢像返個品牌**

最後一項唔過關 → **唔好改嗰篇稿，返去改 `02-voice-profile.md`**。呢個習慣要喺第一日就建立，因為佢決定咗呢個工作台半年後係咪仲有用。

---

## 交付訊息必須包含

唔好報喜不報憂。

- [ ] 生成咗幾多個 agent，點解係呢個數
- [ ] 爬咗幾多條、邊個平台爬唔到、用咗咩 fallback
- [ ] voice profile 信心度 ＋ 理由
- [ ] 邊啲櫃桶空咗、要客戶補咩
- [ ] 冒煙測試嘅實際產出（貼出嚟）
- [ ] 邊啲位係用行業預設填嘅（要 review）

## 常見失敗模式

| 症狀 | 真正原因 | 點救 |
|---|---|---|
| 產出「好順但唔似個品牌」 | voice-profile 太抽象 | 加數字、加禁用詞、加原帖對照 |
| Agent 之間傳唔到嘢 | 上下游檔名唔對 | 逐對核 Inputs / 交付成果 |
| Agent 亂噏數據 | `04-approved-claims.md` 空但冇明寫禁令 | 補上明確禁令 |
| QA 同文案無限退回 | 兩者標準來源唔同 | 統一指向同一份 checklist |
| 跑咗一個月冇進步 | 冇人回寫 MEMORY.md | 把「已補去邊層」設成 review 必填欄 |
| 四個平台內容一樣 | 跳過咗 Master Content 呢層 | 強制先寫 master，再分平台改寫 |
