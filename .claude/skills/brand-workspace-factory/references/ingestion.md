## 先講界線

呢啲唔係客套話，係會影響你交付嘢嘅嘢。

**可以做：**
- 讀公開、唔使登入睇得到嘅內容
- 用平台官方 API（有 token 嘅話）
- 用客戶自己嘅帳號匯出功能攞返自己嘅資料
- 抽統計模式（句長分佈、題材頻率、hashtag 使用率）

**唔好做：**
- 繞過登入牆、驗證碼、或者用假帳號
- 無視 robots.txt 或者平台服務條款
- 高頻請求（一般 1–2 秒一個 request 已經夠，唔使快）
- 儲存個人可識別資料（真實姓名、電話、電郵、頭像）
- 逐句照抄同行內容做「參考素材」

**點解要咁嚴：**除咗法律風險，仲有一個實際理由 —— 照抄嘅工作台會令客戶同全行一模一樣。你賣嘅係差異化，唔係複製能力。抽模式（「呢類帖平均 5 段，每段一句」）有用；抽句子冇用。

**留言處理：**抽用詞同主題，抽完即刻丟原始作者 ID。你要嘅係「原來佢哋叫呢個做『埋身痛』唔係『術後疼痛』」，唔係邊個講。

## 爬三類嘢

### 一、客戶自己嘅帳號 → `voice-profile.md`

**目標數量**：30–50 條。少過 20 條，voice profile 嘅信心度只能算「低」。

抽呢啲：

| 維度 | 點量 |
|---|---|
| 句長 | 平均字數、分佈（有冇長短交錯） |
| 開場 | 頭一句嘅類型：問題／數字／情境／宣告 |
| 段落節奏 | 每段幾句、有冇單句成段 |
| 標點 | 感嘆號密度、有冇用破折號、省略號習慣 |
| Emoji | 密度、位置（句尾／段首／作項目符號）、常用嗰幾個 |
| 稱呼 | 點叫讀者（你／大家／姊妹／寶媽）—— 呢個好影響語氣 |
| CTA | 點收尾、用咩動詞 |
| 禁用 | 從來冇出現過但同行常用嘅字眼 |

**同時標記高表現帖**（讚／收藏／留言明顯高於中位數）。呢啲帖嘅結構抽出嚟就係 `hook-library.md`。

### 二、同行 5–10 個 → `topic-map.md`

唔係抄佢哋。係搵**缺口**。

每條同行內容記低：題材、格式、互動量、留言入面有冇未被解答嘅問題。

然後做兩張表：
- **飽和題**：全行都講到爛（你入場嘅邊際價值低）
- **缺口題**：留言有人問，但冇人正經答過（呢啲就係你嘅機會）

缺口題永遠比飽和題值錢，即使搜尋量低。

### 三、留言區 → `audience-language.md` ＋ `faq.md`

最值錢嗰忽，亦係最多人跳過嗰忽。

抽三類：
- **原話**：受眾點形容自己個問題（一字不改記低用詞）
- **反對理由**：點解佢哋唔買（太貴／唔信／唔啱我／依家未需要）
- **重複問題**：出現三次以上嘅，直接入 `faq.md`

真實受眾用嘅字眼，永遠好過 agent 估出嚟嘅 persona。呢份檔案會直接改善 hook 同 CTA 嘅命中率。

## 各平台實際可行途徑

依現實情況排序。每個平台嘅可行度會變，跑之前確認一次。

| 平台 | 公開讀取 | 官方 API | 實際建議 |
|---|---|---|---|
| **小紅書 XHS** | 網頁版部分公開，限制多 | 冇公開 API | 多數要 fallback。優先叫客戶自己匯出／截圖。同行內容用網頁搜尋逐條睇。 |
| **Instagram** | Profile 公開帖可讀 | Graph API（要 Business 帳號 ＋ 綁 FB Page） | 客戶自己帳號 → 用 Graph API 最乾淨。同行 → 公開讀取或 fallback。 |
| **Threads** | 公開帖可讀 | Threads API（漸進開放） | 網頁公開讀取通常夠用。 |
| **Facebook** | Page 公開帖可讀 | Graph API（Page 需授權） | Page 用 API；群組唔好爬。 |
| **YouTube** | 完全公開 | YouTube Data API（免費額度夠用） | 最易處理。字幕可以直接攞。 |
| **LinkedIn** | 限制嚴 | 受限 | 幾乎一定要 fallback。 |
| **自家網站／Blog** | 完全可讀 | — | 直接爬，注意 robots.txt。 |

**通用做法：**
- User-Agent 用真實嘅，唔好扮空
- 1–2 秒一個 request
- 每條記 Source Receipt：`{title, platform, author_handle, date, url, captured_at}`
- 原始資料落 `data/scraped/<platform>/`，蒸餾產物落 `brand/brain/`。兩者分開，因為原始資料可以重跑蒸餾。

## Fallback：爬唔到點算

**呢步唔可以跳過。** 冇語料就生成 voice profile，係整個 skill 最危險嘅失敗模式 —— 因為輸出睇落好完整，冇人會發現入面係估嘅。

按呢個次序試：

1. **叫客戶用平台匯出功能**（IG／FB 都有「下載你的資訊」）
2. **叫客戶貼 20–30 條佢自己覺得最代表品牌嘅內容**（呢個其實質量最高，因為佢揀嗰啲就係佢認同嘅語氣）
3. **叫客戶截圖**（你讀得到圖）
4. **只做同行同留言部分**，voice profile 標記為「未建立」

如果去到第 4 步：**喺 `voice-profile.md` 第一行明寫「⚠️ 未有真實語料，以下為行業預設，必須由品牌方 review 後替換」**，並且喺交付訊息入面主動講。

一個誠實嘅缺口，好過一個隱藏嘅錯誤。

## 蒸餾方法

用 `scripts/distill.py` 做得到嘅統計部分（句長、emoji、標點、開場分類）。判斷部分自己做。

### `voice-profile.md` 要寫到幾具體

**冇用（唔可驗證）：**
> 語氣親切專業，貼近讀者，用心分享。

**有用（可驗證）：**
> 平均每句 38 字，長短交錯（一段入面通常一長兩短）。
> 開場七成係一條問題，兩成係一個時間情境（「凌晨三點…」），一成係數字。
> 幾乎唔用感嘆號（50 條入面出現 3 次）。
> Emoji 只用喺項目符號位置，常用 ✔️ 同 ·，唔用表情類。
> 稱呼讀者一律用「你」，從來冇用過「寶媽」「親」。
> 收尾固定係一條開放問題，唔用「立即購買」呢類硬 CTA。
> 禁用（同行常用但呢個品牌從來冇用）：「必買」「絕了」「無敵」「姐妹們」。

**驗收標準：**攞兩個唔同嘅寫手（或者兩次獨立生成）睇完呢份檔案去寫同一個題目，出嚟嘅嘢應該似。唔似 = 寫得唔夠具體 = 返去補。

### 常見錯誤

- **把「品牌想成為嘅語氣」寫入去** —— voice profile 記錄嘅係**現況**。想改變語氣係另一個決定，要明確標明，唔好偷偷混入去。
- **只睇高表現帖** —— 高表現帖可能係僥倖。要睇全體嘅中位數行為，高表現帖另外做 hook library。
- **把平台差異壓平** —— 同一個品牌喺小紅書同 LinkedIn 講嘢方式唔同係正常嘅。要分平台記。

## 信心度評級

喺交付訊息入面一定要講。用戶要知道呢個工作台有幾可信。

| 級別 | 條件 | 意思 |
|---|---|---|
| **高** | 自家語料 ≥ 30 條 ＋ 同行 ≥ 5 個 ＋ 留言 ≥ 50 條 | 可以直接開工，第一批稿應該已經似 |
| **中** | 自家語料 15–29 條，或留言不足 | 可以開工，但頭兩星期要逐篇審，執完回寫 |
| **低** | 自家語料 < 15 條，或用咗行業預設 | 當草稿處理。開工前要客戶親自 review voice profile |

評級寫入 `brand/brain/voice-profile.md` 開頭，令之後每個讀到佢嘅 agent 都知道自己踩緊幾實嘅地。
